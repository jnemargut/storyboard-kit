Your workflow is a loop: the agent drafts, you tweak in the editor, you ask the agent for more ("add a panel where she gives up and leaves"), you tweak again, and eventually you export an image. This decision is about what happens to your tweaks each time the loop comes around, and how the final image gets made. Each card runs the same loop and shows where it breaks.

The file is always the truth, and both sides edit it live. Editor changes save within a second as small, targeted edits (layout overrides, text, cast swaps), not a rewrite of the file. The dev server watches the file, so when the agent adds a panel, it appears without wiping your nudges. Export works from the editor button and headlessly via storyboard export (PNG at 2×/3×, PDF, SVG, rendered with resvg and bundled fonts), so agents can attach boards to PRs and docs.

Works well when

  • The agent-plus-editor loop never loses work
  • Git diffs stay readable: small, meaningful edits
  • Agents can export without a browser

Watch out for

  • The hardest to build: file watching, edit-in-place, conflict prompt
  • Needs careful design of the "both changed it" case

A familiar document model: edit, then press Save to write the file. The agent's changes show up when you reload. It's simple and predictable, but the collaboration loop you described (agent drafts, you tweak, ask for more) keeps colliding: forget to save before prompting and someone's work gets thrown away.

The editor is a final polishing step: tweak, export the image, done. Nothing is written back. It's the fastest to build and fine for one-shot boards. But storyboards are iterated (after a crit, after research), and every regenerate throws away the manual work, so people stop tweaking or stop iterating.

Two Files: Story + Layout

late-latte.story.json ← agent owns late-latte.layout.json ← editor owns (positions, sizes, crops) editor text edit on bubble → which file? (story) agent deletes panel 3 → orphaned layout entries
1Agent writes the story file
↓
2Editor writes only the layout file
↓
3Agent regenerates the story freely
if the edit is text or a cast swap ↓
3bEditor must write the story file too, so conflicts return
↓
4Export merges both
Split ownership: the agent owns what happens (story.json) and the editor owns where things sit (layout.json). The two never fight over positions. It's neat until the designer edits a bubble's text or swaps a character in the editor, which are story changes, so the editor writes both files anyway and conflicts come back, now across two files. Panel IDs must also stay stable, or layout entries end up orphaned.

Works well when

  • No conflicts over positions
  • The agent can regenerate the story without fear

Watch out for

  • Text and cast edits still hit the story file
  • Two files to keep in sync, with orphaned entries
  • Harder for agents to reason about

The case against my pick

Live two-way sync is where editors grow their nastiest bugs: file-watcher races, the editor writing a stale copy, an agent and an autosave landing in the same second. For a v1, a lot of that risk could be avoided with A without the conflict UI: last write wins per field, and the editor simply reloads when the file changes. That's almost always fine because humans and agents rarely edit the same field at the same time. Build the "keep mine / take theirs" prompt only if real users hit it.

This recommendation assumes

  • Boards get iterated many times (crits, research findings), not generated once
  • Storyboard files live in git, so readable diffs matter
  • Agents need to produce images on their own (for PR descriptions, docs, Slack), without a browser

What earlier research says about this

  • Mermaid visual editors lose manual layout whenever auto-layout re-runs, or they hide positions in comments. In Miro, a diagram switched to free-form stops syncing with its code. That's the failure A avoids by storing sparse overrides next to the story. CEASG Miro
  • Full Excalidraw JSON rewrites noisy fields on every edit, which makes diffs unreadable. Targeted edits keep git history meaningful. excalidraw #1639
  • resvg renders SVG, including filters, identically on every platform with bundled fonts. It ignores foreignObject and 3D transforms, which is why decision 7 pre-warps screens at export. resvg support table
  • html-to-image-style browser capture silently drops custom fonts and external images. It isn't a reliable export path. html-to-image #534
  • tldraw's file format uses a schema version plus migrations, a good model for keeping storyboard files readable as the tool evolves. tldraw StoreSchema
