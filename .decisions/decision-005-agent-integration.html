Your designers will type something loose into Claude Code, Codex or Cursor. For a good storyboard to come out, the agent has to know the tool exists, know its vocabulary (which poses, shots, scenes and devices exist), write a valid file, and open the editor. A local server exposes tools like add_panel, list_poses and render_preview. The agent calls them instead of editing the file, so invalid data is nearly impossible. But every session pays for all the tool schemas up front, setup differs for each agent (.mcp.json, config.toml, settings.json…), and the Playwright team found CLI + skill used about 4× fewer tokens than their own MCP.

Works well when

Watch out for

  • Install friction across agents
  • Context bloat on every session, used or not
  • Agents lose the ability to just read and edit the file

Three thin layers, each covering a known failure. The CLI does the real work (vocabulary lookups, validation with fix-it hints, dev server, export). The portable skill carries the storyboarding craft ("show the moment before the app", "include a workaround panel") without bloating every session. The case against my pick

Three surfaces means three things that can drift apart: a skill describing a flag the CLI renamed, or an AGENTS.md block pointing at an old command. C alone (AGENTS.md + CLI) scored highest in the one published eval, and it's half the work. You could start with C and add the skill only once you see agents writing technically valid but boring boards (all wide shots, no workaround moments). That's the problem the craft guidance solves. The mitigation if you pick D: generate both the AGENTS.md block and the skill's vocabulary files from the CLI's own schema, so they can't drift.

This recommendation assumes

  • Designers work in a project folder where npx storyboard init can write files (a "storyboards" repo or a folder in the product repo)
  • Every target agent can run shell commands (true for Claude Code, Codex, Cursor, Copilot agent, Gemini CLI)
  • Storytelling quality matters, not only a valid file, so craft guidance earns its place in the skill

What the research says

  • Agent Skills (SKILL.md) became an open spec in Dec 2025. By mid-2026 about 40 products read it, including Claude Code, Codex, Copilot/VS Code, Cursor, Gemini CLI and JetBrains Junie. Agentman agentskills.io
  • Vercel's Next.js evals: the agent never opened the skill 56% of the time. Pass rates were 53% with no docs or with the skill, 79% with the skill plus explicit instructions, and 100% with a compressed AGENTS.md docs index. Vercel
  • AGENTS.md is used by more than 60k projects and was donated to the Linux Foundation's Agentic AI Foundation alongside MCP. Linux Foundation
  • Playwright's benchmark: about 114k tokens via MCP versus about 27k via CLI for the same task. Their 26 tool schemas cost about 3.6k tokens before anything happens. They now point coding agents to the CLI. Better Stack Playwright
  • With 5–10 MCP servers, a session burns 50–67k tokens before the first prompt. Unblocked
  • Remotion ships 15 official skills. Slidev ships a skill plus an MCP endpoint on its dev server, the closest analog to storyboard dev. Remotion Slidev

Where experts disagree

MCP advocates say structured tools are the future and bloat is being fixed (Tool Search defers schemas). CLI advocates point to token numbers and to agents' skill at reading and editing files. What decides it for you: your source of truth is a file the agent edits (decision 1), which favors the CLI camp. MCP is worth adding later for live "change panel 3" edits while the editor is open.
